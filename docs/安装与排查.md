# 安装与排查（含 macOS）

> 适用：`dsh-life-planner` 0.9.27 及以后。插件由**两个 bundle**组成，缺一就会出现"有插件但没学习模式"。

## 1. 两个 bundle 分别负责什么

| 目录 | 包名 | 提供 |
|---|---|---|
| `plugin/` | `@local/dsh-life-planner` | 宿主逻辑、规划页与学习页、43 个工具 |
| `study-preset/` | `@local/dsh-study-preset` | **「学习模式」会话预设**（`study-teach`） |

- 只安装 `plugin/` → 能打开规划页/学习页，但**新建会话的预设列表里没有「学习模式」**。
- 只安装 `study-preset/` → 会话里选得到「学习模式」，但没有页面与工具，进去会报工具不存在。
- 两个都装但**没有重启 DSH** → 预设与插件都未注册，表现同上。

## 2. 安装后自检（按顺序）

1. **设置 → 插件**：列表里应同时出现 `@local/dsh-life-planner` 与 `@local/dsh-study-preset`。
2. **重启 DSH**（不是刷新页面）。
3. **新建会话**：预设下拉里应有「学习模式」；选它并发送任意消息后，
   工具列表里应出现 `study_task_list`、`study_next_questions` 等。
4. **打开插件页面**：标题栏开关打开后，任务树/日历/学习页可正常渲染。
5. 设置弹窗标题显示的版本号应与 `plugin/package.json` 一致（构建期注入）。

## 3. 常见现象与原因

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| 完全看不到插件页面 | 只装了预设，或插件加载失败 | 检查插件列表；看 DSH 日志是否有 `Cannot find package '@deepseek-ai/schemastery'` |
| 页面在，但没有「学习模式」预设 | 只装了 `plugin`，或装完没重启 | 安装 `study-preset` 后重启 |
| 预设可选，但对话说没有 `study_*` 工具 | 插件加载失败 / `studyMode=false` | 检查插件配置与日志 |
| 学习页能开，点新建没反应 | `studyPanel=false` | 插件配置里打开 `studyPanel`，重启 |
| macOS 上 `study_run_program` 报错 | 宿主进程不是 Node（Electron 主进程）时 `process.execPath` 不是 node | 报告现象；可先用普通文件读写替代批量导入 |

## 从 GitHub 更新

用新版本的 `plugin/` 和 `study-preset/` 更新两个已安装的 bundle，然后重启 DSH。插件包与用户数据保存在不同目录。任务和规划书、学习索引、书架、错题、皮肤和外观保存在 `DSH_HOME/life-planner/`。学习知识库保存在各会话工作区的 `learning/`。

从 0.9.37 升级时会尝试将迁移前的 SQLite 快照保存在 `life-planner/backups/`。更换插件包时保留整个数据目录和学习工作区，即可继续使用原有记录和自定义背景。

宿主启动扫描继续执行设置里的自动归档和删除规则。已归档任务达到删除阈值时会清理，默认阈值为 90 天。

## 4. macOS 专项

> **0.9.37 起不再需要 macOS 专用构建**：系统通知（osascript）、PDF（PDFKit 回退）、
> 书架去重（realpath + NFC）、安装门槛（`engines.dsh >=0.2.1-rc.4`）与预设缺包自禁用都已并入主线。

插件本身没有平台限定：路径、`open`/`xdg-open`、通知、`chmod` 封存都有对应分支。
macOS 上需要确认的只有两点：

1. **DSH Desktop 自带运行时**：SQLite 备份接口需要 Node 22.16.0 或同系列更新版本，或 Node ≥ 23.8.0。插件要求 DSH ≥ 0.2.1-rc.4。
2. **系统通知**：macOS 走 `osascript`（无需授权即可弹，但受系统通知设置影响）；
   Windows/Linux 暂无系统级兜底，提醒仍在插件内显示。

3. **`study_run_program` 的子进程**：宿主用 `process.execPath` 启动脚本。
   - 如果 DSH 在 macOS 上以 Node 运行宿主（正常情况），没问题；
   - 如果宿主在 Electron 主进程内，`process.execPath` 是 App 可执行文件，脚本无法运行，
     表现为"导入/批量写库失败"，但页面与出题不受影响。

## 5. 手动安装（macOS 示例）

```bash
# 设 PROFILE 为你的 DSH 配置目录，例如 ~/.dsh/profiles/desktop
PROFILE=~/.dsh/profiles/desktop
ln -s /path/to/plugin      "$PROFILE/node_modules/@local/dsh-life-planner"
ln -s /path/to/study-preset "$PROFILE/node_modules/@local/dsh-study-preset"
```

然后在该 profile 的 `package.json` 里把两个包名加入 `dsh.profile.bundles` 与 `dependencies`，
执行 `pnpm install`，重启 DSH。

## 6. 看日志

DSH Desktop 的控制台/终端会打印插件加载错误，典型关键字：
`life-planner`、`Cannot find package`、`node:sqlite`、`preset-study-teach`。
把这几行贴出来即可定位是"缺包"还是"代码不兼容"。
