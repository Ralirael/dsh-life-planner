# 架构与数据

适用版本：`plugin/package.json` = **0.9.37** ｜ 2026-11-15
本文只讲"东西存在哪、怎么流转"；需求对错看《[需求台账](./需求台账.md)》，界面看《[界面与外观](./界面与外观.md)》，工具与接口看《[工具与路由](./工具与路由.md)》。

## 1. 单任务类型模型

- **一个节点类型**：`items` 表（`index.js:137`）保留 `kind` 列只为兼容历史行；进程启动时把非 `task` 的行一次性归一并补 `status`（`index.js:687-688`），`addItem()` 固定写入 `kind='task'`（`index.js:1153`）。
- **只存意图，状态靠推导**：表里存 `status`（todo/doing/active/paused）与 `completed_at` / `archived_at` / `deleted_at` 时间戳；`done` / `archived` / `blocked` / `deleted` 都由 `derive()` 每次读出时算，不落库。
- **阻塞**：显式 `depends_on` + 子树里未完成的子孙，两者合并去重；写入依赖时做环检测（`wouldCycle`），有环直接拒绝。`task_complete` 默认被阻塞时拒绝完成，需显式 `force`。
- **类别（taskType）**：从顶层祖先的标题推导（`deriveTaskType`，`index.js:1139`），最长 24 字；**创建时算一次**，之后归任务所有——移动或改名不重算，只有显式 patch 才改（`index.js:1230`）。因此类别只用于分组展示，不是树的层级本身。
- **生命周期**：删除先入 `trash`，5 分钟内可 `item.undelete` 恢复，超时由扫描清掉；归档任务保留可恢复，超过 `deleteAfterDays` 才硬删除，硬删除时统一清理通知、错题、计划、学习任务里的引用（`purgeItemReferences`）。
- **学习节点是引用**：`study_tasks.item_id` 指向树里的镜像节点，该节点由学习任务管理，页面不提供手动完成（见《[学习模式](./学习模式.md)》）。

## 2. 数据落在四个地方

| 落点 | 存什么 | 谁写 | 证据 |
|---|---|---|---|
| `$DSH_HOME/life-planner/data.db` | 任务树、规划书、会话开关、设置、通知、回收站、学习索引与旧计划模型 | Host（`index.js` 唯一写入方） | `index.js:38-46`、`:136`（SCHEMA） |
| `$DSH_HOME/life-planner/backups/` | 每次进程启动一份 SQLite 备份，滚动保留最新 20 份 | 启动时 `writeBackup()` | `index.js:44`、`:3100` 起 |
| 会话工作区 `learning/` | 知识本体：`knowledge.db`（words/points）、`index.md`、`materials/` | 学习模式对话经 `study_run_program` 写入 | `openKnowledge`（`index.js:2083`）、`sealLearningFiles`（`:2053`） |
| `ui_state` 表 | 外观（字号/蒙版/背景）与用户命名皮肤 | 客户端 `ui.save` → `saveUiState` | `index.js:180`、`:2821`、`:4293` |

- `data.db` 用 `node:sqlite` 的 `DatabaseSync`，WAL 模式，无原生依赖；旧 JSON 数据第一次启动时自动导入并把原文件改名留档。
- `knowledge.db` **平时是只读文件**（0444），只有 `study_run_program` 执行期间临时解封，结束后重新封上；`learning/index.md` 始终可写，因为它是给人看的说明文档。

## 3. `items` 与 `study_tasks` 双轨

- 既有科目、知识点和日程仍保存在 `subjects`、`topics` 和 `study_plan`。学习任务通过 `study_tasks.subject_id` 关联至多一个科目。旧版多重关联保留在原表中，升级沿用最近一次关联。
- **新轨（现行）**：`study_tasks` 表只是一份**索引**（`id/title/workspace_path/template/summary/item_id/session_id/last_done_day/daily_target/daily_new/daily_review/daily_new/daily_review`），知识内容在各自会话工作区里。一个会话最多一条学习任务（`session_id` 上有唯一索引）。
- 两轨共用同一个任务树：新轨登记时自动在「学习」根下挂一个镜像节点，并打上类别 `学习` 与标签 `学习`，避免落到「未分类」。
- 双轨的取舍与边界写在《[学习模式](./学习模式.md)》；不要在两处各写一遍。

## 4. `settings` 与 `ui_state` 的边界

| | `settings` 表 | `ui_state` 表 |
|---|---|---|
| 内容 | 业务与提醒参数：窗口、提前量、配额、顺延、归档/删除天数、长期提醒周期、每日学习分钟数、类别名与标签库、类别颜色 | 纯展示状态：8 档字号、面板透明度、背景三块（模式/颜色/图片/不透明度/蒙版）、用户命名皮肤、用户默认外观 |
| 校验 | 写入前按 `SETTING_LIMITS` 夹紧并按 `DEFAULT_SETTINGS` 白名单过滤（`index.js:370`、`:900`） | 结构由客户端 `appearance.js` 归一，Host 只做键值存取 |
| 读取 | `GET settings`，页面设置弹窗 | 启动时 `GET ui`，客户端首帧就应用 |
| 导出 | `export` / `import` 会带上（白名单内） | 不进入业务导出；跟随 `ui.save` |

约定：**纯展示状态不要塞进 `settings`，业务参数不要塞进 `ui_state`**。外观必须在 `ui_state`，因为 Web 载体每次启动换端口（换 origin），localStorage 不可靠，只能当首帧缓存。

## 5. 提醒扫描与清理

Host 只有一个每分钟 tick（`scan`，`index.js:979`），同一个 tick 依次做四件事，插件因此不需要调度服务，也不需要会话存在：

1. **学习数据顺延**：过期未完成的学习计划行挪到当前学习日；学习任务的镜像节点每天重新打开、截止时间刷到当天 20:00，且**永不参与过期提醒**。
2. **按年龄清理**：已完成超 `archiveAfterDays`（默认 30）自动归档；已归档超 `deleteAfterDays`（默认 90）硬删除；已投递通知超 30 天、回收站超 1 天、30 天前的每日提示一并清掉（`index.js:1039`）。**未投递的通知不按年龄丢弃**，关窗期间的提醒下次打开仍会出现。
3. **窗口判断**：工作日/周末各一组在线窗口（默认 `10:00-13:00,19:00-02:00` / `10:00-02:00`），窗口外直接跳过；支持跨午夜。
4. **选一条提醒**：候选按截止时间排序，受"相邻提醒间隔（默认 3 分钟）""每窗口非紧急配额（默认 2）""每窗口总上限（默认 6）""顺延上限（默认 48 小时）"约束，最多投递一条；无截止的长期任务按 `longTermReminderHours`（默认 12）周期参与。同一任务已有一条待投递通知时不再重复入队。

系统通知经 Electron 可用时发桌面通知，否则降级为页内提醒条；两种情况都写 `notifications` 表，页面取走后 `notifications.ack`。

## 6. 目录结构与构建

```text
plugin/
├─ index.js            Host：SQLite、迁移、43 个工具、/life-planner/api 路由、提醒、学习逻辑
├─ src/client/         客户端源码（唯一可改的界面源）
│  ├─ index.js         模块加载器契约 + /*__INCLUDES__*/ 标记
│  ├─ app.js           入口对象（inject/apply），插槽注册
│  ├─ i18n.js          zh/en 词典；skin.js 样式令牌；skins.js 皮肤预设
│  ├─ appearance.js    外观模型、蒙版、皮肤快照、持久化
│  ├─ helpers.js / ui.js / api.js / background.js
│  ├─ views/           calendar · tree · board · archive
│  ├─ dialogs/         item-editor · settings · shelf-picker
│  └─ panels/          planning · study 及 5 个学习分区、会话开关
├─ client.js           **构建产物**，不要手改
├─ build-client.mjs    零依赖打包脚本
├─ templates/          knowledge.db 模板：word-bank · outline · custom · ingest · teaching
├─ test/               smoke.mjs · smoke-client.mjs；诊断脚本在 test/tools/
└─ cordis.patch.yml    插入 life-planner 一行（studyMode/studyPanel 默认开启）
```

构建流程（改完 `src/client/` 必做）：

1. `node build-client.mjs` 按 `FIXED` 顺序（i18n → skin → skins → appearance → helpers → ui → background → api）拼根目录模块，再按 `views` → `dialogs` → `panels` 追加，最后放 `app.js`。
2. 脚本会把模块内容替换进 `src/client/index.js` 的 `/*__INCLUDES__*/`，写出 `client.js`。
3. 三重防回归：标记缺失直接失败；除 `app.js` 外任何模块出现顶层 `return {` 直接失败；漏收 `app.js` 也失败。
4. 产物 `client.js` 是纯文本拼接，没有打包器与依赖；失败时不要手改产物，改源码重跑。

## 8. 安装与运行约束

- 一个插件、一个 HTTP 路由前缀；两个侧边栏入口共用同一套存储，不另起服务器。
- 宿主侧改动必须重启 DSH；纯客户端改动刷新页面即可（`client.js` 是构建产物）。
- 插件保持被动：不主动开会话、不注入提示、不自动创建学习任务（见台账对应行）。
