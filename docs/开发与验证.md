# 开发与验证

适用版本：`plugin/package.json` = **0.9.37** ｜ 2026-11-15
环境要求（来自 `plugin/package.json`）：Node **≥22.5**（`node:sqlite` 是内置模块）、DSH **≥0.2.2-rc.2**。零原生依赖、零构建依赖。

## 1. 构建

```powershell
cd plugin
node build-client.mjs              # src/client/** → client.js（唯一构建步骤）
node --check index.js              # 宿主语法
node --check client.js             # 产物语法
```

- `client.js` 是**构建产物**，永远不要手改；改 `src/client/` 后必须重新构建，否则页面用的是旧代码。
- 构建顺序有意义：`i18n → skin → skins → appearance → helpers → ui → background → api`，再 `views → dialogs → panels`，最后 `app.js`。新文件默认按目录追加，只有"必须提前加载"时才加进 `FIXED`。
- 构建脚本有三重防回归：缺 `/*__INCLUDES__*/` 标记、除 `app.js` 外出现顶层 `return {`、漏收 `app.js`，任一命中都直接失败。

## 2. 冒烟测试

```powershell
cd plugin
node test/smoke.mjs          # 宿主：工具（含总数 42）、门控、依赖与环、树操作、路由、SQLite 落盘
node test/smoke-client.mjs   # 客户端：模块注册、5 个插槽、locale
```

- 两份都必须全绿才算改完；断言条数以脚本自身输出为准，不在文档里写死数字。
- 宿主冒烟与 `process.cwd()` 解耦，可在任意目录运行。
- 诊断脚本（不参与验收，按需用）：`test/tools/inspect-db.mjs` 看真实库的表与行数、`test/tools/inspect-ages.mjs` 看归档/删除年龄分布、`test/tools/route-usage.mjs` 看哪些路由客户端从不调用、`test/tools/bench-storage.mjs` 对比存储体量。

## 3. 安装、重启、刷新

| 改动位置 | 生效方式 |
|---|---|
| `plugin/index.js`、`cordis.patch.yml`、`package.json`、`Config` 开关 | **重启 DSH**（插件在启动时注册工具与路由） |
| `plugin/src/client/**` | `node build-client.mjs` 后**刷新页面** |
| `client.js` 之外的静态资源（`icon.svg`、`locale/*.json`） | 重启 DSH |
| 外观/皮肤/背景 | 即时生效，无需重启（写 `ui_state`） |

约束与坑：

- **客户端代码改动不能靠 HMR**：插件热替换只同步启用/禁用，替换包代码后要重新加载页面，否则侧栏图标与开关会短暂消失。
- **不要 import `@deepseek-ai/dsh-tools`**：bundle 以链接方式安装时按真实路径解析，工作区没有该包会在激活时报 `ERR_MODULE_NOT_FOUND`；工具定义直接写注册表接受的原始 JSON Schema。
- **不要另起服务器**：插件只用宿主 `webServer` 注册 `/life-planner/api` 前缀；Web 载体每次启动换端口，这也正是外观必须存 `ui_state` 的原因。
- **`knowledge.db` 是只读文件**：要改库只能走 `study_run_program`；用普通写文件工具改会因权限失败。
- 安装方式：插件管理器把 `plugin/` 作为 bundle 目录安装；`study-preset/` 是可选预设包，装完要**新开会话**才能选到「学习模式」。

## 4. 验收清单（10 条以内）

1. 设置弹窗标题显示 `v` + `plugin/package.json` 的版本（构建期注入 `__PLUGIN_VERSION__`，见 `plugin/build-client.mjs`）。
2. 侧边栏两个入口都在：规划页 5 个视图、学习页 5 个分区都能打开且不报错。
3. 工作树第一层是**类别**；空类别不出现；类别头 `+` 新建时类别已预填，且能在弹窗里改。
4. 新建子任务 → 父任务显示被阻塞；勾父任务弹出阻塞清单，确认后可强制完成。
5. 在会话标题栏打开开关 → 工具可用；关闭 → 工具消失；学习模式会话无需先开开关。
6. 外观：改字号立即生效；背景改「图片」后出现蒙版（默认左侧 25%），面板呈 15% 半透明；保存命名皮肤、设为默认、刷新页面后仍保持。
7. 学习页「习惯」本周时间表能显示、但页面无输入框（由对话写入）。
8. 学习对话里一轮 5–10 题一次问完，答错后错题集出现对应条目；该条目熟练度满 10 后错题自动消失。
9. 导出 JSON → 改动 → 导入，任务、设置、学习索引都能回填。
10. `node test/smoke.mjs` 与 `node test/smoke-client.mjs` 全绿，`node --check` 两个产物通过。

## 5. 打包发布

发布物放在 `dist/`（不进版本库）：

```
dist/dsh-life-planner-<version>/
  README.md  LICENSE  .gitignore  CHANGELOG.md
  docs/      8 份现行文档（不含 audit/ 与 archive/）
  plugin/    源码 + templates + locale + test（不含 node_modules）
  study-preset/
dist/dsh-life-planner-<version>.zip
```

打包步骤：

1. 复制 `plugin/`（排除 `node_modules`、`pnpm-lock.yaml`）、`study-preset/`；
2. 复制 8 份文档与 `CHANGELOG.md`：`README`、`速查`、`需求台账`、`架构与数据`、`界面与外观`、`学习模式`、`工具与路由`、`开发与验证`；
3. 写入公开发布的 `README.md`（安装/启用/隐私/开发/License）、`LICENSE`（MIT）、`.gitignore`；
4. **脱敏检查**：不得出现本机路径、用户名、`data.db`、截图与个人记录；
5. 在发布目录执行 `node build-client.mjs` 确认可复现（24 模块 / 版本号一致）；
6. 解压 zip → 在 `plugin/` 里 `pnpm install --prod` → 跑两份冒烟，确认可分发给他人。
