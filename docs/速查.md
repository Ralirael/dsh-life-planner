# 速查（给 agent 与管理者的单页）

> 一页查全：工具、路由、表结构、构建验证、常见坑。版本以 `plugin/package.json` 为准。
> 规则细节只写在各专题文档；本页只负责"去哪查、能不能做"。

## 1. 工具（43 个）

| 族 | 数量 | 工具 |
|---|---|---|
| 任务/规划 | 12 | `planner_overview` `planner_get_plan` `planner_update_plan` `item_add` `item_update` `item_move` `item_archive` `item_delete` `item_reorder` `task_complete` `task_depends` `planner_reset` |
| 学习 | 31 | 见 [工具与路由](./工具与路由.md) 第 1 节完整表（含参数与语义） |

**权限**：一条 `when` 规则决定可见性——会话开关打开，或当前会话预设是 `study-teach`。
开关打开 = 43 个工具全部可用（含 `study_run_program`）；`studyMode=false` 时学习工具整体隐藏。
`studyPanel=false` 只影响页面路由，学习类写路由返回 403。

必知语义（学习）：

- `study_register_task(dailyNew, dailyReview)`：登记；同一工作区重复登记会更新。
- `study_next_questions(taskId, count, {newCount, reviewCount})`：新内容 = `learned=0`，复习 = `learned=1` 的弱项；0 分照常出题但 3 天内答对不加分。
- `study_answer`：±1；到 10 掌握并删错题；两段目标都达标自动完成今天。
- `study_progress(taskId, days)`：按日的 `target/answered/newMet/done` + `streak`，周检查的数据源。
- `study_set_target(taskId, dailyNew, dailyReview)`：默认目标；`study_set_day_target(taskId, newTarget, reviewTarget)`：只改今天。
- `study_plan_done` / `study_plan_*` 属**旧计划模型**，纯学习任务不要用；完成今天用自动判定或 `study_finish_today`。

## 4. `knowledge.db` 最小 DDL（工作区内，由 `study_run_program` 写）

```sql
CREATE TABLE cards (
  id TEXT PRIMARY KEY, front TEXT NOT NULL, back TEXT NOT NULL,
  extra TEXT DEFAULT '', proficiency INTEGER NOT NULL DEFAULT 4,
  learned INTEGER NOT NULL DEFAULT 0,
  source TEXT DEFAULT '', created_at TEXT NOT NULL, updated_at TEXT
);
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);
-- tree 模板用 points(id,title,detail,proficiency,learned,updated_at)
-- bank 模板另需 questions(id,prompt,answer,options,explanation,kind,difficulty,proficiency,learned)
--            与 question_points(question_id,point_id,weight)
```

必需列：`id / proficiency / learned / source / created_at / updated_at`；无 `learned` 时宿主按"全部复习"兼容。

## 5. 构建与验证（在 `plugin/` 下）

```bash
node build-client.mjs          # 生成 client.js（唯一产物，不手改）
node --check index.js          # 宿主语法
node --check client.js         # 客户端语法
node test/smoke.mjs            # 宿主：43 工具、路由、学习/计划/树完整性
node test/smoke-client.mjs     # 客户端：插槽、构建顺序、组件结构
```

生效方式：宿主改动 → **重启 DSH**；客户端改动 → 刷新页面（版本号在 `package.json`，构建期注入）。

## 6. 常见坑

1. `knowledge.db` 平时 0444 只读：批量写只能走 `study_run_program`；`learning/index.md` 可写。
2. 学习日按**凌晨 04:00** 切分；判断今天用 `study_task_list` 的 `doneToday`，不要自己按 0 点推。
3. 不要用 `node:sqlite` 的 `BEGIN` 嵌套：宿主 `write()` 已可重入，别再包一层事务。
4. 不要给可能包含 `position: fixed` 弹层的容器加 `backdrop-filter`/`transform`——下拉会错位。
5. 客户端源由 `build-client.mjs` 按固定顺序拼接，共用作用域：新增文件若需早加载要加进 `FIXED`，且不得有重复顶层声明（构建会报错）。
6. 不通过 PowerShell 改含中文的源文件（会乱码）；用编辑工具或 Node UTF-8 脚本。
7. `client.js` 不能手改；版本只在 `package.json` 与 `__PLUGIN_VERSION__`。
8. 文档里的行号会漂移，按"文件 + 函数名"搜索。
9. `study_habits` 固定 14 天、无参数；完成率属于旧计划模型，新轨判定用 `study_progress`。
10. `study_shelf_add` 的 `kind` 可省略（自动识别）。
11. 书架目录列表最多 800 项，超出会标「已截断」；挂给学习任务时若源已在工作区内则只引用不复制。
12. `planner_reset(all)` 保留设置与习惯历史，但会清空任务、学习任务、知识点与错题。
13. 动 `plugin/index.js` 的迁移段时：先 `ALTER` 补齐所有列，再 `UPDATE` 回填，否则旧库升级会失败。
